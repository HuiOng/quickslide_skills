Emerging operating model

The future workflow should connect strategy to handover without losing context.

The aim is not only to generate output faster. It is to preserve intent from the first idea through to user stories and a simple mockup engineers can discuss.

1. ExploreFrame problem, users, and constraints with AI.
2. StandardizeTurn recurring rules into a skill or agent pattern.
3. PlanAgree scope, assumptions, risks, and success measures.
4. PRDGenerate a product brief with linked requirements.
5. StoriesMap PRD needs into user stories and acceptance criteria.
6. MockupCreate a simple HTML prototype for handover.
Claim: traceability beats isolated outputs04 / 08

Standardization decision

I am learning when to make a skill, and when to make an agent.

The distinction matters because the reusable asset should match the type of work: knowledge standard, execution workflow, or a combination of both.

Make a skill when... The problem is repeated judgment. Examples: preferred design standards, PRD structure, writing style, evidence checklist, output quality bar, reusable deck patterns.
Make an agent when... The problem is repeated action. Examples: gather context, ask clarifying questions, draft PRD, generate stories, create mockup, validate output, prepare handover.

Risks and guardrails

The main risk is not AI output quality. It is unclear ownership of standards.

To make this useful at work, each workflow needs a clear quality bar, validation method, and decision owner before it is reused.

Risk Going straight to output Guardrail: start with problem framing, assumptions, and acceptance criteria.
Risk Reusable standards become vague Guardrail: define examples, anti-examples, and validation checks inside the skill.
Risk Mockup looks final but is not aligned Guardrail: treat mockups as discussion artifacts tied back to user stories.
Claim: governance can be lightweight but explicit07 / 08
