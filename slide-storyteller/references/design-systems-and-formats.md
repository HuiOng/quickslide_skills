# Design Systems And Formats

Use this reference when a user asks for better-looking slides, professional templates, Google-style design, comic/story visuals, infographics, timelines, roadmaps, dashboards, or a deck that should feel less generic.

## Inspiration Anchors

Before choosing a design system, consider channeling one of these reference aesthetics. Name a specific direction in your concept memo:

- **Pentagram annual reports** (bold geometry, restrained palette, asymmetric layouts, confident oversize type, editorial pacing)
- **FiveThirtyEight data stories** (annotated charts, clear hierarchies, supporting statistics in body copy, newsroom rhythm)
- **New York Times Upshot** (strong claims in headlines, slopegraphs and small multiples, data-led storytelling, magazine spacing)
- **Stripe or Linear product pages** (minimal card grids, whitespace-heavy, strong use of negative space, clean sans-serif type, single accent color)
- **Wieden+Kennedy or other creative agency posters** (bold blocks, high contrast, expressive section dividers, one hero visual per slide, graphic composition)
- **IDEO case studies** (strong imagery, generous margins, clear step-by-step journeys, human focus, editorial warmth)
- **TED Talk slides** (minimal text, high-impact imagery, simple diagrams, restrained use of graphics)
- **Financial Times visual journalism** (authoritative charts, news rhythm, credibility through craft, muted palette)

Pick one as your north star when writing art direction concepts. Channel the *feeling* and *rhythm*, not the brand identity.

## Design System Routing

Pick one primary system and one optional accent system. Do not mix many styles in one deck.

| System | Best For | Visual Rules | Avoid |
|---|---|---|---|
| Modern executive | strategy, leadership, investment, board-style updates | white or near-white canvas, strict grid, one accent color, dense but calm charts, precise labels | decorative blobs, vague icons, oversized quote slides |
| Google/Material-inspired | product, tech, workflow, training, internal tools | clean cards, Material Symbols-style icons, Google-like blue/red/yellow/green accents used sparingly, strong spacing, simple diagrams | copying Google brand identity, multicolor decoration without meaning |
| Summer garden professional | resume portfolios, personal websites, warm leadership stories, friendly training | light canvas, sage/leaf greens, pale sky, soft sunlight, restrained petal accents, botanical SVG shapes, airy editorial spacing | beige-only palettes, childish flowers, cluttered borders, low-contrast pastel text |
| High-end editorial | portfolio, keynote, thought leadership, founder story | large type, strong image crops, magazine-like pacing, generous margins, few words | tiny captions, busy charts, template-looking sections |
| Graphic poster | campaigns, creative concepts, launch narratives | bold blocks, geometric shapes, strong contrast, one hero visual per slide, expressive section dividers | low-contrast text, random shapes, overfilled slides |
| Comic storyboard | beginner education, playful explainers, process stories | panels, speech/thought bubbles, sequential beats, recurring original character, clean line art | dense data, childish tone for serious audiences, fake brand characters |
| Data newsroom | analytics, research readouts, market stories | claim headline, annotated chart, source note, callout labels, one key number | chart dumps, unlabelled axes, ornamental dashboards |
| Workshop canvas | brainstorms, training, team rituals | sticky-note rhythm, swimlanes, journey maps, exercises, facilitator notes | making every slide look like a whiteboard |

## Slide Format Library

Choose the format before styling the slide. The proof object should determine the layout.

| Need | Use | Layout Guidance |
|---|---|---|
| Show change over time | timeline, roadmap, Gantt, milestone rail | 3-7 milestones; put dates on a stable axis; separate past, now, next |
| Show a customer/user experience | journey map, storyboard, service blueprint | stages across columns; emotion or friction row; evidence row; opportunity row |
| Explain how something works | process flow, flywheel, system map | use arrows only for real sequence; group inputs, mechanism, outputs |
| Compare options | 2x2, tradeoff table, decision matrix | define criteria first; highlight the recommended option; keep scoring simple |
| Show hierarchy | pyramid, stack, architecture layers | largest or foundational layer at bottom; label what changes between layers |
| Show portfolio or proof | case-study card, before/after, artifact wall | pair the claim with a screenshot, metric, quote, or shipped artifact |
| Show ideation or prototype progress | compact UI mockup, search result snippet, wireframe fragment | recreate only the key interaction or evidence; keep labels readable and avoid full screenshot dumps unless inspection matters |
| Teach beginners | comic panels, numbered steps, checklist, worked example | one concept per slide; show the exact action; add a takeaway line |
| Tell a strategy story | situation-tension-choice-plan | repeat the same visual grammar so the argument feels inevitable |
| Report status | RAG table, milestone tracker, risk register | use status colors consistently; include owner, date, decision needed |
| Present data | annotated chart, slopegraph, small multiples, waterfall | title states the insight; callouts explain the "so what"; minimize chart ink |

## Format Families for Variety Budget

For the format variety budget (≥4 distinct families per deck, no two adjacent slides with the same family), use these format families as the basis for your slide plan:

| Family | Use | Example Slide |
|---|---|---|
| Cover | opening, section divider, closing | hero title, large image, section headline with decorative mark |
| Full-bleed type | emphasis, headline, standalone insight | oversize claim, drop cap intro, large pull quote with thin rule |
| Data hero | metrics, charts, annotated visuals | large annotated chart with 3 callouts, before/after metric pair, slopegraph |
| Card grid | multiple equal-weight ideas, capability lists, features | 3–4 cards with icon/title/description, checklist tiles, working-model tiles |
| Timeline/rail | sequences, milestones, roadmaps, launch plans | horizontal or vertical milestone strip, rollout phases, learning arc |
| Quote/callout spread | testimony, insight, reflection, feedback | full-bleed single quote, "heard → changed" flow, working-model reflection |
| Diagram/flow | systems, processes, relationships, logic | process map, journey map, architecture diagram, decision tree, 2x2 matrix |
| Photo+caption | editorial, story, before/after, artifact | full-bleed photo with short claim, artifact wall, case-study hero image |
| Table/grid | structured comparison, operating model, status | availability table, capability matrix, RAG status grid, criteria table |
| Comic/storyboard | narrative, teaching, beginner steps, scenario | sequential panels, numbered steps with illustrations, character-driven walkthrough |

Plan your deck to distribute formats across families. A 7-slide deck might use: cover (family 1) + full-bleed type (family 2) + data hero (family 3) + card grid (family 4) + timeline (family 1, allowed to repeat non-adjacent) + quote spread (family 2) + closing cover (family 1). This repeats families but never on adjacent slides.

- Hypermatic free Figma presentation templates: useful for startup and pitch-deck structures that can be exported with its tooling. Start at `https://www.hypermatic.com/templates/presentations/`.

## Editorial Moves and Signature Devices

When a visual system feels tired or a slide lacks distinction, use a concrete editorial device to reset attention and vary the proof object.

**Typography-led moves:**
- **Drop cap or oversize numeral**: start a section with a large number or letter (200%–400% size) that anchors the line and draws the eye
- **Full-bleed headline**: let a headline or key phrase run edge-to-edge with generous line height; pair with minimal supporting text below
- **Pull quote or callout spread**: dedicate a whole slide to one strong quote or insight, set large (72pt+), with a thin leader rule above and a one-line attribution below
- **Column rule or ribbon**: run a thin accent-color rule or ribbon down the left or center to separate sections or guide the eye through a multi-column layout

**Layout-led moves:**
- **Asymmetric grid (70/30)**: place a headline or image on 70% of the slide, supporting copy or small secondary object on 30%; breaks the symmetry of centered cards
- **Photo + caption spread**: full-bleed photography on one side with a short claim and small proof note on the other; creates editorial magazine feel
- **Stacked titles with callout**: headline, subheading, and one bold number or metric stacked tight with careful spacing, no background box
- **Timeline or milestone rail**: horizontal strip with 3–5 dated milestones, past/now/future clearly marked; good for launches, rollouts, or learning arcs

**Data-led moves:**
- **Annotated chart as hero**: one large, simple chart with 2–3 text callouts labeling the insight; no legend or unnecessary gridlines
- **Before/after metric pair**: side-by-side cards showing starting point and change (e.g., "3 days to review" → "6 hours to review"); emphasizes impact
- **Small multiples or slopegraph**: 3–4 related charts in a row or cascade, each showing one variable; easier to compare than one dense dashboard

**Composition-led moves:**
- **Whitespace-heavy slide**: one or two elements floating in generous whitespace; feels confident and forces the viewer to focus
- **Flush-left or flush-right layout**: break the center-aligned default; align content to one edge for dynamic feel
- **Diagonal or staggered arrangement**: offset cards or objects along a diagonal line rather than a grid; adds visual energy

Use one signature device per deck section to signal transitions and maintain visual interest. Avoid overloading a single slide with multiple devices.

## Formatting Rules That Make Decks Feel Professional

- Establish a 12-column or 8-column grid and align every major object to it.
- Use 1-2 typefaces and no more than 3 text sizes per slide family.
- Build reusable slide masters in the deck: cover, section divider, claim + proof, chart, timeline, table, quote, closing.
- Make the headline a claim, then reserve the largest object for the proof.
- Match visual weight to content hierarchy. Background/context notes should look lighter and less important than key updates, decisions, or asks.
- Do not style background/context as the same card pattern used for key points. Use lighter treatments such as inline notes, small captions, side rules, or subdued callouts so they read as setup rather than another main item.
- Vary slide formats across the deck. Reuse the visual system, not the same layout; alternate proof objects such as cards, timeline rails, tables, flows, quotes, diagrams, before/after views, and icon-led asks.
- When a user provides a screenshot to illustrate an idea, prefer a simplified, editable proof mockup that captures the key pattern. If the user asks to include the picture exactly, or if the recreated mockup remains visually off, use the actual screenshot file as a contained proof image. Preserve the screenshot's main proportions and hierarchy as a wide proof object rather than compressing it into a tiny card thumbnail. Do not place explanatory text beside the mockup if it squeezes or distorts the screenshot layout; put the explanation above it or in a separate card.
- Keep each proof object inside or directly under the section it supports. Avoid leaving a short card beside a tall card in the same grid row when equal-height stretching creates a large empty box; stack the sections or rebalance the grid.
- When responsive mockups contain optional controls, give those controls explicit classes for hiding or wrapping at narrower widths. Do not rely on fragile `nth-of-type` selectors that can miss the intended chip and allow overflow.
- For toolbar-like UI mockups, use a flex row for inputs, chips, and icon buttons when alignment matters. Use grid for structured result rows, but avoid grid in the toolbar if it makes controls look uneven or crooked.
- Keep a consistent footer system for section, source, date, or confidentiality.
- Use color semantically: status, category, stage, or emphasis. Avoid random rainbow palettes.
- Use diagrams as editable shapes, not screenshots, unless the source artifact itself must be shown.
- Add a credits slide when third-party templates, icons, photos, or illustrations require attribution.

## Alignment And Spacing QA

Before final delivery, check core slide patterns at desktop, tablet, and mobile widths.

- Numbers, badges, icons, and labels should sit inside their intended tile or row and align consistently.
- Generic text styles must not accidentally override positioning for badges, step numbers, or small labels.
- Cards and tiles should fit their content. Reduce padding, min-height, icon size, or decorative shapes when short content leaves large empty areas.
- Do not stack cards into a tall column too early. Keep multi-column rows at tablet widths when the text still fits comfortably.
- Use stable dimensions and grid tracks for repeated UI elements so hover states, labels, icons, or line wraps do not shift the layout.
- Check that titles, body text, footers, badges, and decorative elements do not overlap at common viewport sizes.
- If a user comments that spacing is wasteful or alignment is off, fix layout CSS before rewriting the message.

## Summer Garden Professional

Use this direction when the user asks for light colors, summer, flowers, nature, warm but professional, soft personal branding, or a resume/portfolio that should feel approachable.

Palette:

- leaf: `#477b5f`
- deep leaf: `#23483a`
- sage: `#dfeadb`
- mint: `#eef7ee`
- pale sky: `#d9edf5`
- sunlight: `#ffe8a8`
- petal: `#f7c7bb`
- peach paper: `#fff4e6`
- warm paper: `#fffdf8`

Layout rules:

- Use a light canvas with generous whitespace and editorial typography.
- Use botanical shapes as a supporting motif: leaves, stems, soft petals, growth arcs, garden-map lines.
- Keep flowers abstract and sparse so the design reads professional, not decorative stationery.
- Pair a serif headline with a clean sans-serif body when the story is personal or portfolio-oriented.
- Use sage/leaf for structure, sunlight for emphasis, petal only for warmth, and sky/mint for calm section backgrounds.
- Good formats: resume hero, timeline, case-study cards, credential wall, leadership story, portfolio proof blocks, closing statement.

## Visual Critique Pass

Before final delivery, scan the rendered deck for:

- too many slides using the same layout
- repeated card grids where a different proof format would communicate better
- number, icon, badge, or label alignment that drifts outside the visual grid
- tiles or cards that are much taller than their content requires
- responsive breakpoints that create awkward stacks or excessive vertical gaps
- section dividers that do not reset attention
- timelines without clear date spacing or "now" marker
- comic/story slides where panels do not read left-to-right/top-to-bottom
- Google/Material-style decks that overuse brand colors
- charts whose conclusion is not visible from the headline and annotation
- credits missing for free assets that require attribution
